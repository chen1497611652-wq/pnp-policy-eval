## §1 一句话结论

`src/fk_check.py` 是一个检查数据集标签可不可信的小工具。之所以写它，是因为我们用的教程里有一段采集脚本记错了。

采集脚本在每一时刻记两条：`observation.state`（此刻末端在哪，xyz + 姿态）和 `action`（此刻该怎么动，六个关节角 + 夹爪）。但它把 `action` 记成了机械臂**自己当前的关节角**，而不是下发的命令。于是每条样本就变成了「你现在末端在这 → 你现在关节角是这些」—— 里面没有任何"下一步该做什么"的信息。部署时模型只能输出"保持不动"的关节角。

可 `action` 是关节角、`state` 是末端位姿，两个量不在同一个空间，没法直接相减。所以要先做 **FK（正运动学）**：把 `action` 正解成"照这个关节角摆好，末端会落在哪"，再拿去和 `state` 比。

**判定是反直觉的**：两者的差**恰好等于 0**（落在 float32 噪声内）才是坏消息 —— 那说明 `action` 就是当前实测关节角的副本；差**非零、且随帧变化**才是正常的，那才叫"命令 vs 实测"之间的跟踪误差。

数据已在 **D9 重采修复**。本文给出可复现的判定工具 [`src/fk_check.py`](../src/fk_check.py)，并用它同时验了"坏的"和"好的"两份数据。

## §2 现象：一个"什么都不做"的策略

`【历史记录】`（D8，策略复刻首次闭环部署）

- 机械臂能自主移动到杯子附近，但停在杯口上方**小幅抖动**，不下降、不抓取
- 持续 **1131 秒**仿真时间无任何进展 —— 而正常演示只需 **116 秒**
- 决定性的那一眼：末端高度 z 从 `1.0024` → `1.0023`，**只差 0.1 毫米**。它不是"动作慢"，它是**根本没在做事**
- **调参无效**：`temporal_ensemble_coeff=0.9`（论文默认值的 90 倍）改了也没用

最后一条是关键判断：一个**滞后**的策略会慢，但**不会在 1131 秒里连 z 都不动**。所以问题不在推理、不在采样，在**数据**。

## §3 根因：三环证据链

```
第 1 环（读代码）：step() 不推进物理，只把目标写进 self.q；
                  而 get_joint_state() 读的是仿真里的测量值
第 2 环（读代码）：采集循环里，ee_pose 和 joint_q 之间没有任何物理推进
第 3 环（跑实验）：FK(action) ≡ state，差值 0.000000        【历史记录·D8】
   ↓
每条样本 = 「你现在的末端位姿 → 你现在的关节角」
   ↓
训练学到的是静态映射，样本里没有任何"下一步该做什么"的信息
   ↓
部署时模型输出"让手保持在原地"的关节角 → 关节空转、永不成功、调参无用
```

**为什么特别隐蔽**：`step()` 自己的 docstring 写着 `state of the environment after taking the action` —— **意图**是"动作之后的状态"，**实现**上却没推进物理（真正的推进在 `step_env()` 里，而 `step_env()` 只推进 `dt = 0.002` 秒）。**文档与实现不一致**，肉眼读代码极容易漏掉。

## §4 决定性实验：FK 检验 ⭐

### 4.1 原理

`action` 是**关节角**（7 维：6 关节 + 夹爪），`observation.state` 是**末端位姿**（6 维：x, y, z, roll, pitch, yaw）。两者不在同一个空间，**没法直接相减**。

FK（正运动学）是桥：给一组关节角，算出末端会落在哪。

```python
fk_pose(env, actions[i])   # "假如机械臂照 action 里记的关节角摆好，末端在哪"
compare_pose(states[i], fk_pose(env, actions[i]))   # 再和 state 记的末端位姿比
```

| 结果 | 含义 |
|---|---|
| **非零，且随帧变化** | ✅ 正常：一个是目标、一个是实际，差的就是**跟踪误差** |
| **恒等于 0**（float32 噪声内） | ❌ 坏的：`action` 记的不是命令，是实测值 |

**为什么这是决定性的**：

- 若 `action` 是**命令**（目标关节角）→ FK(action) 指向"想去的地方"，与当前 `state` 必然有差
- 若 `action` 是**当前实测关节角** → FK(action) **必须精确等于** `state`（同一个量、同一段 FK 代码，差只可能来自 float32）

**两种可能，一次分清。** 差为 0 才是坏消息 —— 因为"命令"和"实测"之间永远有物理误差，只有"同一个东西"才会差 0。

### 4.2 怎么跑

在 PowerShell 里跑（普通终端也一样）：

```powershell
python -m src.fk_check --parquet "<你的数据集根目录>\data\chunk-000\episode_000000.parquet"
```

帧号**不用手填**：`default_frames(n)` 按行数自动取 5 个等分点（含首尾）。D8 那天把帧号写死成 `[0,600,1200,1800,2320]`，而数据集只有 2259 行 → 直接 `IndexError`。

位置差和姿态差**分开打印** —— D8 用 `np.abs(s - ee).max()` 把米和弧度混在一起取 max，得出的数没有物理意义。

### 4.3 结果并排

| 数据集 | 最大位置差 | 判定 |
|---|---|---|
| `demo_data_example`（bug 版） | **1.49e-08 m** | ❌ `[BAD]` action 是实测关节角 |
| `demo_data`（D9 重采后） | **9.782 mm**（工具抽的 5 帧内） | ✅ `[OK]` action 是命令 |

`【本次实测】`两份都能跑，判定相反 —— 这就是"两组对照"。

> `demo_data_example` 的 5 个抽样帧全部落在 float32 噪声内（最大 1.49e-08 m），是干净的 bug 指纹。
> `demo_data` 全序列（2259 帧）的位置差范围是 **52.9 μm ~ 14.807 mm**，工具只抽 5 帧，所以打印的是抽样内最大值。

### 4.4 误差的形状：它随速度变化，不是固定偏移

`【本次实测】`全序列 2259 帧，位置差与"帧间移动速度"的关系：

| 机械臂状态 | 帧数 | 位置差中位数 | 位置差最大 |
|---|---|---|---|
| 静止（< 0.5 mm/s） | 1582 | 1.921 mm | 14.713 mm |
| 运动（> 5 mm/s） | 437 | **6.210 mm** | **14.807 mm** |

相关系数 **r = 0.481**。

**运动时误差约为静止时的 3 倍** —— 这是控制器滞后：跑得越快，实际越追不上命令（和你端一杯水走路一样，站定时水面纹丝不动，走得越快晃得越厉害）。

**这个形状额外排除了一种替代解释**：如果这个差是"坐标系没对齐"造成的**固定偏移**，它应该大致恒定，**不会随速度变化** ⇒ **这个差是物理的（控制器滞后），不是几何的**。

> ⚠️ **但也别把这个形状读强了** —— 它排除掉的是"固定偏移"，不是"速度是唯一原因"：
>
> - `r = 0.481` ⇒ **r² = 0.23**，只有 23% 的方差能由速度解释，只能算**中等相关**
> - 最大误差来自**帧 1570–1575 一个连续的块**：速度已经掉到 0.45 mm/s，误差还停在 14.7 mm 下不来。速度解释不了这几帧，更像是抓放瞬间的**接触 / 稳态误差**（位置控制顶着外力时追不上命令）
> - 静止时误差中位数是 **1.9 mm，不是 0**（只有个别帧，如帧 2253，降到 52.9 μm）。"停下来差就消失"这个说法**过强了**，实测是"明显变小，但不为零" —— 而这本身就够用：**只要它不为零，`action` 就不可能是实测值的副本**
>
> 所以论据取**中位数之比（6.2 vs 1.9 mm）**，不取最大值之比 —— 中位数不被那几个异常帧支配；取最大值会得出"静止也差 14.7 mm"的错误印象。

### 4.5 ⭐ 追加实验：差是"当前命令"还是"下一步目标"？

`【本次实测】`在运动帧（> 5 mm/s）上，看 FK(action[i]) 离哪一帧的 `state` 最近：

| 比较对象 | 位置差中位数 |
|---|---|
| `state[i-1]` | 11.411 mm |
| `state[i]` | 6.210 mm |
| **`state[i+1]`** | **1.987 mm** ← 最近 |
| `state[i+2]` | 5.701 mm |

**结论：`action[i]` 是最接近"下一步"的那个量**，比同帧近 3 倍。

也就是 `action[i]` = 第 i 步下发的**命令**，`state[i+1]` = 执行完的结果，中间那 **1.987 mm** 是控制器/IK 的稳态误差。

这正是行为克隆数据集**该有的**语义：`(observation_i, action_i)` 表示"看到这个，就该发这个命令，于是走到 observation_{i+1}"。

## §5 影响：低 loss 反而是坏消息

因为 `action = FK⁻¹(state)`（动作是状态的函数），模型**最省力的解是完全无视图像**，只背下 `state → action` 这个映射。图像一张都不用看，loss 就能压得很低。

**这重新解释了那个一直可疑的数字：Mean action error = 0.008。** `【历史记录】`

> 一开始把它读成"模型学会了"。现在看，它其实是"**模型学会了一个恒等映射**" —— 这活儿太简单了，0.008 是理所当然的。

**残余误差哪来的**：`train_loss` 收敛在 0.039 而不是 0，是因为 **IK 冗余** —— 同一个末端位姿对应无数组关节角，模型只看静态位姿，无法判断该用哪一组。

> 📌 **这条能带走**：指标好看 ≠ 真的学会。**先问一句「这件事，最偷懒的做法能拿多少分？」**
> 如果偷懒的解和用心的解分数差不多，这个指标就证明不了什么。

## §6 修复

**方案 A（推荐，已采用）**：采集时记录**命令的目标关节角**，而不是 `step()` 的返回值。

```python
# 从
joint_q = PnPEnv.step(action)
# 改成
PnPEnv.step(action)
joint_q = np.concatenate([PnPEnv.compute_q, [PnPEnv.gripper_cmd_scalar]]).astype(np.float32)
```

**❌ 方案 B（走错的，留着当教训）**：想"在 `step()` 后补一句 `step_env()` 再读 `get_joint_state()`"。

**无效。** `step_env()` 只推进 `dt = 0.002` 秒，而关节是位置控制、惯性大，2 毫秒几乎没动 —— **退化问题一点没解决**。

> **教训**：一个"看起来在修 bug"的改动，如果不理解它的**量级**，可能只是把同一个错误换了个写法。

## §7 ⚠️ 这个检验能证明什么、不能证明什么 ⭐

**一个检验的价值 = 它排除掉的东西，不多不少。**

| ✅ 能确定 | 依据 |
|---|---|
| `action` 和 `state` 是**两个不同的量** | bug 版精确等于 0；`demo_data` 最小差 52.9 μm，**比 float32 噪声（1.2e-7 m）大 440 倍** `【本次实测】` |
| 这个差是**物理的，不是几何的** | 差随速度变化（运动 6.2 mm vs 静止 1.9 mm，r = 0.48），固定坐标系偏移不会这样 `【本次实测】` |
| `action[i]` 是**下一步的命令**，不是当前实测值 | FK(action[i]) 离 `state[i+1]` 最近（1.987 mm），比同帧（6.210 mm）近 3 倍 `【本次实测】` |
| 数据是**修复后**采的，`act_y` 的训练输入是干净的 | 上面三条 ⇒ 那次 Success 是有意义的，不是"模型学会了输出当前状态"的假象 |

| ❌ 不能确定 | 为什么 |
|---|---|
| **演示本身"好"** | 检验的是**两列之间的关系自洽**，不是绝对正确性。一份内部自洽但毫无用处的演示照样通过 |
| **没有零星坏帧** | 工具只抽 **5 帧 / 2259 帧**。如果 bug 只影响某一小段，抽样会漏掉（§4.4 的全序列扫描是补救，但那是我另外跑的，不在工具里） |
| **这套结论能否外推到别的数据集** | `demo_data_example` 是坏的、`demo_data` 是好的 —— 但每份新数据都得**自己跑一遍**，不能靠文件名判断 |

> 📌 **体检不证明你健康，它只筛掉最要命的几种病。**

**关于证据强度**：本文最强的三条是 `【本次实测】`（可以复现）；§2 的"1131 秒"和 §5 的 loss 数字是 `【历史记录】`，原始文件已不可得。写清楚这一点，比把两类证据混在一起讲更有说服力。

## §8 怎么在你自己数据上跑

```powershell
python -m src.fk_check --parquet "<你的数据集根目录>\data\chunk-000\episode_000000.parquet"
```

**文件名不用猜** —— 它是 LeRobot 的规范，写在数据集自己的 `meta/info.json` 里（`data_path` 字段）：

```
data/chunk-{episode_chunk:03d}/episode_{episode_index:06d}.parquet
```

- `episode_000000.parquet` = 第 1 集（集号 6 位补零），**一集一个 parquet**
- `chunk-000` = 第 0 个分块（分块号 3 位补零）；`chunks_size = 1000`，所以第 0–999 集都落在 `chunk-000`
- **真正要换成你自己的，只有前面那个根目录** —— 数据集收在哪，那里就是什么

> 路径怎么找：打开 `<数据集根目录>/meta/info.json` 看 `data_path` 字段，或者在 VS Code 里点进 `data/chunk-000/`，右键那个 `.parquet` → **Copy Path**。

看到什么结果，就是什么含义：

| 输出 | 含义 | 你该做什么 |
|---|---|---|
| `[OK]` 位置差几毫米 ~ 十几毫米 | `action` 是命令，数据健康 | 可以拿来训练 |
| `[BAD]` 位置差落在 float32 噪声内 | `action` 是实测关节角，数据是坏的 | 按 §6 修采集脚本，重采 |
| `[??]` 位置差大于 0.5 m | 这份数据集的 `state` 不是末端位姿，本工具不适用 | 先确认采集时的 `state_type` |

> ⚠️ 这个工具**只适用于 `observation.state` 是末端位姿（ee_pose）的数据集**。
> 如果数据的 `state` 本身就是关节角（例如 `omy_pnp_language`），它会拿关节角去减末端位姿 —— 两者不是同一种量，判定无意义。此时工具会打印 `[??]` 而不是给结论。

可选项：`--frames 0,500,1000` 自己指定抽样帧；`--config <path>` 换一份配置（默认 `configs/default.yaml`）。
